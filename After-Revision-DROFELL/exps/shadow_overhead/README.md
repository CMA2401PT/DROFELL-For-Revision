# Shadow-State Overhead Experiment

## Purpose

Measure retained bytes and update CPU time of control-side Shadow state across model size, failed-handle shard size, and recovery-window length. The experiment does not measure steady-state model computation because a Shadow is not a compute worker.

## Two entry points

### Analyze existing local events

```bash
export DROFELL_PY="${DROFELL_PY:-python}"

PYTHONPATH="$PWD" "$DROFELL_PY" \
  exps/shadow_overhead/analyze.py \
  --run-id <local-run-id>
```

Input should contain `shadow_state_snapshot` events generated by one commit and instrumentation schema. The analyzer should record input SHA-256.

### Independent sweep

```bash
PYTHONPATH="$PWD" "$DROFELL_PY" \
  exps/shadow_overhead/run.py \
  --python "$DROFELL_PY" \
  --run-id shadow-overhead
```

The runner covers 7B/70B and several shard sizes and restarts the network for every case. Consult `run.py --help` and source constants for the current matrix.

## Interpretation and acceptance

- Retained bytes count objects actually held during the Shadow lifecycle.
- Checkpoint tensors, replay tasks, and Python metadata are recorded separately.
- `update_cpu_ns` is cumulative CPU time, not recovery wall-clock time.
- Instrumentation JSONL I/O alters the hot path, so the run does not report throughput.
- Model size, shard size, and recovery-window length are separate axes.
- Reject aggregation when snapshots are missing, schemas differ, or hashes do not match.

Generated JSONL, CSV, logs, and summaries are not version-controlled.
